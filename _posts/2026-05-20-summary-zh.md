## [Mozilla 弃用 asm.js，标志一个时代的结束](https://spidermonkey.dev/blog/2026/05/20/saying-goodbye-to-asmjs.html) ⭐️ 8.0/10

Mozilla 的 SpiderMonkey 团队宣布弃用 asm.js（一种能在浏览器中实现接近原生性能的 JavaScript 子集），并计划最终从 Firefox 中移除对其的支持。 这标志着一项开创性网络技术的终结，该技术为 WebAssembly 铺平了道路，并证明了 Figma 等复杂应用可以在浏览器中运行，从而影响了现代网络性能格局。 Asm.js 是 JavaScript 的一个严格子集，支持提前优化，但已被 WebAssembly (Wasm) 取代，后者提供更小的二进制格式和更快的解析速度。此次弃用是在 Wasm 自 2017 年发布以来被广泛采用之后进行的。

hackernews · eqrion · May 20, 12:01 · [社区讨论](https://news.ycombinator.com/item?id=48206340)

**背景**: Asm.js 由 Mozilla 于 2013 年推出，作为对 Google 的 Native Client (NaCl) 和 Portable Native Client (PNaCl) 的回应，旨在为网络带来接近原生的性能。它允许开发者使用 Emscripten 将 C/C++ 代码编译为 JavaScript 的子集，从而使游戏和设计工具等应用能在浏览器中运行。WebAssembly 由主要浏览器厂商共同开发，旨在解决 asm.js 的局限性，并于 2019 年成为 W3C 推荐标准。

## [C 语言未定义行为：比你想象的更普遍](https://blog.habets.se/2026/05/Everything-in-C-is-undefined-behavior.html) ⭐️ 8.0/10

一篇文章探讨了 C 语言中晦涩且令人惊讶的未定义行为案例，包括 volatile 访问和未对齐指针，认为几乎任何操作在特定情况下都可能是 UB。 理解 UB 的真实范围对于依赖 C 语言编写安全关键或性能敏感代码的系统程序员至关重要，因为编译器会利用 UB 进行优化，从而可能静默地破坏程序。 文章指出，根据 C 标准，volatile 读取是副作用，当与同一对象上的其他副作用未排序时会导致 UB；并且仅仅持有未对齐指针就是 UB，而不仅仅是解引用它。

hackernews · lycopodiopsida · May 20, 06:07 · [社区讨论](https://news.ycombinator.com/item?id=48203698)

**背景**: C 语言中的未定义行为（UB）意味着语言规范对程序行为没有要求，允许编译器假设此类操作永远不会发生。这可以实现激进的优化，但可能导致崩溃、错误输出或安全漏洞。常见例子包括有符号整数溢出和缓冲区溢出。
